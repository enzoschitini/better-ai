Visão Geral

O módulo context_builder transforma uma busca na web feita pela Tavily em um contexto em markdown pronto para ser usado por modelos de linguagem, junto com a lista de URLs analisadas. Ele é composto por duas classes:

  • TavilyContextBuilder: executa o pipeline (busca, filtragem por score, conversão para markdown e extração das URLs).
  • TavilyResearchRunner: monta a configuração da busca, aplicando valores padrão, e aciona o TavilyContextBuilder.

A busca em si é feita por um objeto "researcher", normalmente o TavilyDeepResearch. O pipeline é exposto pela API no endpoint POST /deep-research/context-builder.

Fluxo de Execução

  1. Configuração da busca: TavilyResearchRunner.run() chama build_search_config(), que valida query e max_results, aplica os valores padrão (search_depth, topic e include_answer) e incorpora parâmetros extras.
  2. Pipeline: o runner entrega a configuração a TavilyContextBuilder.build_context().
  3. Busca: search() chama researcher.start_search() com a configuração.
  4. Filtragem: filter_results() mantém só os resultados com score maior ou igual a min_score, remove as chaves globais descartáveis e o raw_content de cada resultado.
  5. Markdown: to_markdown() converte a resposta filtrada em um texto em markdown.
  6. URLs: get_web_sites() reúne as URLs dos resultados mantidos.
  7. Retorno: build_context() devolve um dicionário com as chaves markdown e urls.
  8. Erros: em cada etapa, uma exceção é registrada com o ApplicationTracing (nível ERROR) e relançada como RuntimeError com uma mensagem descritiva.

Variáveis de Ambiente

  • TAVILY_API_KEY: chave de API da Tavily, lida pelo TavilyDeepResearch ao ser instanciado.

Pontos Importantes da Arquitetura e Insights

  • Separação de responsabilidades: o TavilyResearchRunner cuida da configuração e dos padrões; o TavilyContextBuilder cuida do processamento; o researcher cuida do acesso à Tavily.
  • Injeção de dependência: o builder recebe o researcher e o runner recebe o builder, o que facilita a substituição de qualquer peça.
  • Filtragem por relevância: só entram no contexto os resultados com score maior ou igual a min_score (padrão 0.5).
  • Contexto enxuto: as chaves response_time, follow_up_questions, images e request_id da resposta e o raw_content de cada resultado são removidos antes da conversão.
  • Tratamento de erros uniforme: toda falha é registrada com ApplicationTracing (flag "Deep Research") e relançada como RuntimeError.
  • Logs informativos desativados: o tracer é criado com show_info_logs=False, e as chamadas tracer.INFO do módulo estão comentadas.

Formato do Markdown Gerado

O método to_markdown() produz um texto com esta estrutura, repetindo o bloco de fonte para cada resultado:


# Consulta
**Pergunta:**
{query}

---

## Resposta resumida
{answer}

---

## Fontes analisadas

### 1. {title}
- **URL:** {url}
- **Score de relevância:** {score}

**Conteúdo:**
{content}

---

O score é arredondado para 5 casas decimais. Se um resultado não tiver título, usa-se "Sem título".

Endpoint da API

O endpoint monta um TavilyDeepResearch, um TavilyContextBuilder (com o min_score recebido) e um TavilyResearchRunner, e devolve o resultado de run() no campo result da resposta padrão. Ele exige a chave de API da BetterAI no cabeçalho X-API-Key (a validação é ignorada quando LOCAL=true).

Corpo da requisição

CampoTipoDescriçãoValor Padrão
querystrConsulta ou assunto principal da pesquisa."What are the latest AI trends in the healthcare industry?"
search_depth"basic" | "advanced"Profundidade da pesquisa: basic para uma visão geral rápida, advanced para uma busca mais completa."advanced"
max_resultsint (1 a 100)Número máximo de resultados a recuperar e incluir no contexto.35
topicstrCategoria ou domínio da pesquisa. Exemplos: general, news, finance."general"
include_answerboolSe deve incluir uma resposta gerada a partir dos resultados.True
min_scorefloat (0.0 a 1.0)Score mínimo de relevância; resultados abaixo dele são descartados.0.5

Exemplo de requisição


curl -X POST "http://localhost:8000/deep-research/context-builder" \
  -H "X-API-Key: SUA_CHAVE" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Quais as principais tendências de IA em 2026?",
    "search_depth": "advanced",
    "max_results": 10,
    "topic": "general",
    "include_answer": true,
    "min_score": 0.5
  }'

Resposta de sucesso

A resposta segue o formato padronizado da API, com job_id, status, result e métricas de tempo. Em result, vêm o markdown e as URLs:


{
  "job_id": "job_...",
  "status": "success",
  "status_code": 200,
  "result": {
    "markdown": "# Consulta\n...",
    "urls": ["https://..."]
  },
  "time": {
    "start": "2026-01-01 10:00:00",
    "end": "2026-01-01 10:00:05",
    "duration_seconds": 5.0
  }
}

Em caso de falha, a resposta traz status igual a error, status_code 500 e um objeto error com type e message. Os parâmetros e exemplos completos da API estão em Web Service Network - API.

Descrição das Classes e Métodos

Classe TavilyContextBuilder

Descrição

Executa o pipeline que transforma uma busca na web em contexto em markdown: busca, filtragem por score, conversão para markdown e extração das URLs.

Argumentos do Construtor

ArgumentoTipoDescriçãoValor Padrão
researcherobjetoObjeto com o método start_search, normalmente um TavilyDeepResearch.—
min_scorefloatScore mínimo para manter um resultado.0.5
remove_keysList[str] | NoneChaves removidas do nível global da resposta.["response_time", "follow_up_questions", "images", "request_id"]

Métodos

1. search

Descrição

Executa a busca chamando researcher.start_search() com a configuração recebida.

Argumentos

  • search_config (Dict[str, Any]): configuração da busca (por exemplo, query, max_results, search_depth).

Retornos

  • Dict[str, Any]: resposta bruta da busca.

Raises

  • RuntimeError: se a busca falhar ("Error during web search").

Exemplos


raw = builder.search({"query": "tendências de IA em 2026", "max_results": 5})

2. filter_results

Descrição

Mantém apenas os resultados cujo score seja maior ou igual a min_score, remove as chaves globais definidas em remove_keys e remove o raw_content de cada resultado.

Argumentos

  • research_results (Dict[str, Any]): resposta bruta da busca.

Retornos

  • Dict[str, Any]: resposta filtrada.

Raises

  • RuntimeError: se a filtragem falhar ("Error filtering web search results").

Exemplos


filtered = builder.filter_results(raw)

3. to_markdown

Descrição

Converte a resposta filtrada em texto markdown, com a consulta, a resposta resumida e as fontes analisadas (título, URL, score de relevância e conteúdo).

Argumentos

  • data (Dict[str, Any]): resposta filtrada.

Retornos

  • str: texto em markdown.

Raises

  • RuntimeError: se a conversão falhar ("Error converting web search results to markdown").

Exemplos


markdown = builder.to_markdown(filtered)

4. get_web_sites

Descrição

Retorna a lista com a URL de cada resultado da resposta filtrada.

Argumentos

  • filtered_result (dict): resposta filtrada, com a chave results.

Retornos

  • list: URLs dos resultados.

Exemplos


urls = builder.get_web_sites(filtered)

5. build_context

Descrição

Executa o pipeline completo: search, filter_results, to_markdown e get_web_sites.

Argumentos

  • search_config (Dict[str, Any]): configuração da busca.

Retornos

  • dict: dicionário com as chaves markdown (texto em markdown) e urls (lista de URLs analisadas).

Raises

  • RuntimeError: se qualquer etapa falhar ("Error building research context").

Exemplos


context = builder.build_context({"query": "tendências de IA em 2026", "max_results": 5})
print(context["markdown"])
print(context["urls"])

Classe TavilyResearchRunner

Descrição

Monta a configuração da busca, aplicando valores padrão, e aciona o TavilyContextBuilder. É o ponto de entrada mais simples para gerar um contexto.

Argumentos do Construtor

ArgumentoTipoDescriçãoValor Padrão
builderobjetoObjeto com o método build_context, normalmente um TavilyContextBuilder.—
default_search_depthstrProfundidade usada quando search_depth não é informada."advanced"
default_topicstrTópico usado quando topic não é informado."general"
default_include_answerboolValor usado quando include_answer não é informado.True

Métodos

1. build_search_config

Descrição

Monta o dicionário de configuração da busca, validando os campos obrigatórios, aplicando os valores padrão e incorporando extra_params.

Argumentos

  • query (str): consulta. Obrigatória.
  • max_results (int): número máximo de resultados. Obrigatório.
  • search_depth (Optional[str]): profundidade da busca. Se omitida, usa o padrão do runner.
  • topic (Optional[str]): tópico da busca. Se omitido, usa o padrão do runner.
  • include_answer (Optional[bool]): se deve incluir a resposta resumida. Se omitido, usa o padrão do runner.
  • extra_params (Optional[Dict[str, Any]]): parâmetros adicionais incorporados à configuração; podem sobrescrever os campos acima.

Todos os argumentos são nomeados (keyword-only).

Retornos

  • Dict[str, Any]: configuração da busca.

Raises

  • ValueError: se query estiver vazia ou se max_results for None.

Exemplos


config = runner.build_search_config(
    query="tendências de IA em 2026",
    max_results=5,
    extra_params={"include_domains": ["arxiv.org"]},
)

2. run

Descrição

Monta a configuração com build_search_config e executa o pipeline com builder.build_context.

Argumentos

  • Os mesmos de build_search_config, todos nomeados.

Retornos

  • dict: dicionário com as chaves markdown e urls, como em build_context.

Raises

  • ValueError: se query ou max_results não forem informados.
  • RuntimeError: se alguma etapa do pipeline falhar.

Exemplos


researcher = TavilyDeepResearch()

builder = TavilyContextBuilder(
    researcher=researcher,
    min_score=0.5
)

runner = TavilyResearchRunner(builder)

context = runner.run(
    query="Quais as principais tendências de IA em 2026?",
    search_depth="advanced",
    max_results=2,
    topic="general",
    include_answer=True
)

print(context["markdown"])
