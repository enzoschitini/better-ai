Panoramica

La classe JsonToPydantic è stata sviluppata per facilitare la conversione dinamica di dizionari JSON in modelli Pydantic con tipizzazione automatica dei campi. Questo processo è molto utile quando si lavora con dati JSON non strutturati o variabili e si ha la necessità di validare e manipolare tali dati sfruttando la robustezza offerta da Pydantic.

In sostanza, la classe permette di trasformare un JSON arbitrario in una classe Pydantic generata a runtime, deducendo i tipi di base dei valori (come stringa, intero, float, booleano, liste e dizionari). Questo semplifica i workflow che coinvolgono validazione dei dati, test o manipolazione in cui lo schema JSON non è definito in anticipo.

In pratica, basta creare un'istanza di JsonToPydantic, passare il JSON come dizionario ai metodi della classe e ottenere automaticamente modelli e istanze tipizzati, pronti per la validazione e per un accesso facilitato ai dati.

Flusso di Esecuzione

  1. Istanzia la classe JsonToPydantic, passando opzionalmente un nome per il modello Pydantic che verrà creato (model_name).
  2. Chiama il metodo build_model passando un dizionario JSON per creare un modello Pydantic dinamico. Questo metodo deduce i tipi dei campi in base ai valori del dizionario.
  3. Utilizza il metodo parse per creare un'istanza del modello Pydantic generato in precedenza, popolata con i dati del dizionario JSON.
  4. Se una qualsiasi fase fallisce (deduzione dei tipi, costruzione del modello, istanziazione), la classe solleva eccezioni di tipo RuntimeError per indicare errori esplicativi.

Punti Importanti dell'Architettura e Insights

  • La classe utilizza la libreria pydantic per creare modelli dinamicamente (create_model) e per una validazione robusta dei dati.
  • La deduzione eseguita dal metodo _infer_type copre i tipi comuni di Python e restituisce Any quando il tipo non è chiaramente identificato.
  • L'uso di eccezioni di tipo RuntimeError con messaggi specifici facilita la comprensione di possibili errori nel flusso.
  • La classe non dipende da variabili d'ambiente esterne per funzionare.
  • L'approccio adottato facilita la creazione di schemi dinamici, utile per i sistemi che consumano JSON con struttura variabile o sconosciuta in fase di sviluppo.

Descrizione della Classe e dei Metodi

Classe JsonToPydantic

Descrizione

Classe per la creazione dinamica di modelli Pydantic a partire da dizionari JSON, che consente validazione e tipizzazione automatica dei campi in base ai dati ricevuti.

Argomenti del Costruttore

ArgomentoTipoDescrizioneValore Predefinito
model_namestrNome del modello Pydantic creato"DynamicModel"

Metodi

1. __init__

Descrizione

Inizializza l'oggetto definendo il nome del modello Pydantic che verrà creato dinamicamente.

Argomenti

  • model_name (str): Nome del modello Pydantic (opzionale).

Valori di ritorno

  • Non restituisce alcun valore.

Raises

  • Nessuna.

Esempi


converter = JsonToPydantic()  # modelo padrão "DynamicModel"
converter_custom = JsonToPydantic("MeuModelo")

2. _infer_type

Descrizione

Identifica il tipo Python corrispondente al valore fornito per definire il tipo del campo nel modello.

Argomenti

  • value (Any): Valore da analizzare e tipizzare.

Valori di ritorno

  • Type: Tipo Python corrispondente (str, int, float, bool, list, dict oppure Any).

Raises

  • RuntimeError: Nel caso in cui si verifichi un errore durante la deduzione del tipo.

Esempi


tipo = converter._infer_type("texto")  # retorna <class 'str'>
tipo = converter._infer_type(123)      # retorna <class 'int'>

3. build_model

Descrizione

Costruisce e restituisce un modello Pydantic generato dinamicamente con campi e tipi basati sul dizionario JSON fornito.

Argomenti

  • data (Dict[str, Any]): Dizionario con i dati per la deduzione del modello.

Valori di ritorno

  • Type[BaseModel]: Classe del modello Pydantic creato.

Raises

  • RuntimeError: Nel caso in cui si verifichi un errore durante la creazione del modello.

Esempi


modelo = converter.build_model({"nome": "Ana", "idade": 30})
# Retorna um modelo equivalente a:
# class DynamicModel(BaseModel):
#     nome: str
#     idade: int

4. parse

Descrizione

Genera un modello Pydantic a partire dai dati e restituisce un'istanza popolata con tali dati.

Argomenti

  • data (Dict[str, Any]): Dizionario JSON da convertire in istanza del modello.

Valori di ritorno

  • BaseModel: Istanza del modello Pydantic con i dati validati.

Raises

  • RuntimeError: Nel caso in cui si verifichi un errore nella creazione o nella validazione dell'istanza.

Esempi


if __name__ == "__main__":
    data = {
        "text": "A empresa TechNova está crescendo rapidamente.",
        "task": "Se o nome da empresa for TechNova, troque por BetterAI"
    }
    parser = JsonToPydantic("ResearchRequest")
    request = parser.parse(data)

    print(request)
    print(type(request))

Mappatura delle forme di schema

1. Input accettati dalla rotta

Formato della richiesta: multipart/form-data.

Campi:

  • job_id (obbligatorio): str
  • metadata (obbligatorio): str contenente JSON valido
  • document_schema (obbligatorio): str contenente JSON valido
  • file (obbligatorio): file
  • config (opzionale): str contenente JSON valido

Regole sul file in questa rotta:

  • Estensioni consentite: txt, md, pdf, docx
  • Dimensione massima: 50 MB

Errori comuni di input:

  • Invalid JSON in metadata
  • Invalid JSON in schema
  • Invalid JSON in config

2. Importante: chi interpreta il document_schema

  • document_schema non viene convertito da JsonToPydantic.
  • Nella rotta, viene convertito da GeneratePydanticSchema + FieldMetadataParser.
  • JsonToPydantic viene usato nell'agente per input_data e config_data.

3. Tutte le forme di document_schema accettate nella pratica

3.1 Campo dichiarativo semplice


{
    "summary": {
        "type": "str",
        "description": "Resumo do conteúdo do arquivo"
    }
}

3.2 Campo dichiarativo con required, default, example


{
    "title": {
        "type": "str",
        "required": true,
        "description": "Título principal",
        "example": "Relatório de Q2"
    },
    "confidence": {
        "type": "float",
        "required": false,
        "default": 0.0,
        "description": "Confianca da extração"
    }
}

3.3 Campo dichiarativo con validazione della dimensione


{
    "abstract": {
        "type": "str",
        "description": "Resumo detalhado",
        "min_length": 20,
        "max_length": 500
    }
}

3.4 Lista dichiarativa di primitivi


{
    "keywords": {
        "type": "list",
        "items": {
            "type": "str"
        },
        "description": "Palavras-chave"
    }
}

3.5 Lista dichiarativa di oggetti


{
    "entities": {
        "type": "list",
        "items": {
            "type": "object",
            "properties": {
                "name": {
                    "type": "str",
                    "description": "Nome"
                },
                "category": {
                    "type": "str",
                    "description": "Categoria"
                },
                "score": {
                    "type": "float",
                    "description": "Pontuação"
                }
            }
        }
    }
}

3.6 Deduzione automatica tramite esempio (senza type)


{
    "summary": "texto exemplo",
    "score": 0.98,
    "approved": true
}

3.7 Deduzione di oggetto annidato


{
    "invoice": {
        "number": "INV-001",
        "total": 199.9,
        "paid": false
    }
}

3.8 Deduzione di lista di oggetti


{
    "items": [
        {
            "sku": "A-1",
            "quantity": 2,
            "unit_price": 49.9
        }
    ]
}

3.9 Deduzione con lista vuota


{
    "items": []
}

In questo caso, il tipo diventa una lista generica.

3.10 Schema ibrido (dichiarativo + deduzione nello stesso payload)


{
    "summary": {
        "type": "str",
        "description": "Resumo final"
    },
    "stats": {
        "pages": 12,
        "language": "pt-BR"
    }
}

4. Mappatura dei tipi in modalità dichiarativa

Valori riconosciuti in type:

  • str
  • int
  • float
  • bool
  • list
  • dict

Se il tipo non viene riconosciuto, ricade in Any.

5. Regole e limitazioni importanti

  1. Se il campo è un dict e possiede la chiave type, viene trattato come metadato dichiarativo.
  2. Per type = "list", items è obbligatorio.
  3. Una lista dichiarativa di oggetti richiede items.type = "object" con properties.
  4. I campi senza required sono opzionali per impostazione predefinita.
  5. Il parser accetta una struttura ibrida, mescolando campi dichiarativi e dedotti.
