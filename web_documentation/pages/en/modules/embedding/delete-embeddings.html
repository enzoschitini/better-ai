Delete Embeddings

The DeleteEmbeddings class was developed to manage the deletion of embeddings stored in a vector database.

On this page

    #Overview

    The DeleteEmbeddings class was developed to manage the deletion of embeddings stored in a vector database. It allows removing specific entries according to the target keys and values provided, ensuring fine-grained control over the data that must be eliminated. This class is especially useful in systems that store vector representations for semantic search, where keeping the base up to date is crucial.

    It solves the problem of optimizing the cleanup and maintenance of vector data, enabling selective deletion across multiple namespaces, including a global scope, with safety and validation of the targets that may be affected. In practice, a developer can use it to erase data related to specific knowledge bases, keeping the integrity of the data in other contexts.

    #Execution Flow

    1. Initialization: The class is instantiated with the vector database settings (optional). If no settings are passed, default values are loaded from the general configuration.
    2. Target Validation: Before any deletion, the target keys are validated to ensure they are within the allowed limits, avoiding deletion outside the desired scope.
    3. Establishing the Connection: The connection to the vector database is created, initializing the clients needed to perform the operations.
    4. Running the Deletion: For each target key-value pair, it performs the deletion in the configured namespaces (main and, optionally, global), collecting events that detail the deleted vectors.
    5. Aggregating the Results: The events are aggregated by namespace, summing the quantities of deleted vectors and preparing a summary.
    6. Returning the Result: At the end, a dictionary is returned with the success of the operation, the total of deleted vectors and details per namespace.

    #Environment Variables

    No environment variables are used directly by this class. The vector database settings are obtained through the GetConfig configuration object.

    #Key Architecture Points and Insights

    • Modular and Private Design: The class uses private methods to organize the steps (validation, connection, deletion, aggregation), ensuring cohesion and clarity in the flow.
    • Configuration Injection: Allows overriding the default settings, making it easier to use across multiple environments and in tests.
    • Traces and Logs: Integration with the tracing system (ApplicationTracing) for detailed recording of actions, useful for auditing and debugging.
    • Handling of Multiple Namespaces: The class supports deletion in distinct namespaces, including an optional global scope, which indicates flexibility for more complex storage scenarios.
    • Robust Error Handling: Exceptions are caught and re-raised with clear messages, keeping control of the flow and transparency of the errors.
    • Use of External Classes: Depends on the GetConfig, VectorDBConnection and ApplicationTracing classes, which indicates integration with configuration modules, database access and the logging/tracing system.

    #3. _validate_targets

    Description

    Checks whether the target keys for deletion are among the allowed keys to limit the scope of the operation, raising an error otherwise.

    Arguments

    • target_keys (list): List of target key names to validate.
    • targets_to_limit (list or None): List of keys allowed for deletion. If None, no restriction applies.

    Returns

    • Does not return a value.

    Raises

    • ValueError: if no value of target_keys is contained in targets_to_limit.

    Examples

    # Valida que "knowledge_base_id" está entre os alvos permitidos
_delete._validate_targets(["knowledge_base_id"], ["knowledge_base_id"])

# Levanta erro se sem correspondência
# _delete._validate_targets(["user_id"], ["knowledge_base_id"])  # ValueError

    #4. _delete_from_namespaces

    Description

    Deletes the documents that have a target key and value in the main namespace and, optionally, in the global namespace, returning detailed events.

    Arguments

    • target_name (str): Name of the target key for deletion.
    • target_value (str): Associated value to filter the documents to delete.
    • main_ns (str): Main namespace where the deletion will be done.
    • global_ns (str): Global namespace for optional deletion.
    • save_global (bool): Defines whether to also delete in the global namespace.

    Returns

    • list: List of events with the deletion details in each namespace.

    Raises

    • None directly (internal exceptions would be propagated).

    Examples

    events = delete_embeddings._delete_from_namespaces(
    "knowledge_base_id", "kb_001", "main_ns", "global_ns", True
)
# events contém detalhes de vetores deletados em cada namespace

    #5. _aggregate_events

    Description

    Aggregates a list of deletion events, summing quantities and organizing them by namespace to ease analysis and structuring of the result.

    Arguments

    • events (list): List of individual deletion events.

    Returns

    • list: List aggregated by namespace containing totals and detailed items.

    Raises

    • None.

    Examples

    aggregated = delete_embeddings._aggregate_events(events)
# aggregated terá estrutura resumida por namespaces

    #6. delete

    Description

    Main public method that orchestrates the whole deletion operation: validates the targets, connects to the database, runs deletions on all key-value pairs, aggregates and returns the consolidated results.

    Arguments

    • target_keys (list): List of key names for deletion.
    • target_values (list): List of corresponding values to filter deletions.
    • targets_to_limit (list or None): Optional list to restrict the keys that can be used for deletion.

    Returns

    • dict: Dictionary containing:
      • success (bool): Indicates whether the operation succeeded.
      • summary (dict): Summary with the total of deleted vectors and the number of namespaces affected.
      • deleted_by_namespace (list): Detailed listing by namespace.

    Raises

    • ValueError: If the target keys are not allowed.
    • RuntimeError: If the connection or the operation on the vector database fails.

    if __name__ == "__main__":
    import json

    payload = {
        "vector_db_settings": {
            "index_name": "my_index",
            "embedding_model": "text-embedding-3-small",
            "main_namespace": "main_ns",
            "global_namespace": "global_ns",
        },
        "target_keys": ["knowledge_base_id"],
        "target_values": ["kb_12345"],
        "targets_to_limit": ["knowledge_base_id"]
    }

    delete_embeddings = DeleteEmbeddings()
    result = delete_embeddings.delete(
        target_keys=payload["target_keys"],
        target_values=payload["target_values"],
        targets_to_limit=payload["targets_to_limit"]
    )

    print(json.dumps(result, indent=2))
