Payload Builder

Questa è una documentazione dettagliata e didattica della classe PayloadBuilder, progettata per standardizzare la telemetria e il logging delle applicazioni Python.

In questa pagina

    #Panoramica

    La classe PayloadBuilder agisce come una fabbrica di messaggi e strutture di dati. Il suo obiettivo principale è garantire che, indipendentemente da dove venga generato un log nel sistema, abbia una struttura coerente.

    Risolve il problema comune dei log disorganizzati, permettendo allo sviluppatore di generare sia una stringa leggibile per gli umani (console) sia un oggetto JSON strutturato per database NoSQL (come MongoDB), mantenendo la tracciabilità tramite ID e metadati.

    #Flusso di Esecuzione

    Il flusso tipico di utilizzo della classe segue questi passi:

    1. Istanziazione: L'oggetto viene creato, di solito ricevendo il contesto globale (ID del log, nome del file o flag di categoria).
    2. Elaborazione dei Metadati: Quando registra un evento, la classe valuta se esistono dati extra (metadata) e come devono essere mostrati (formattati come JSON indentato o come stringa semplice).
    3. Composizione del Messaggio: Il metodo build_message concatena le parti (funzione, messaggio, contesto) usando un delimitatore (|).
    4. Strutturazione per la Persistenza: Se il log deve essere salvato nel database, il metodo build_mongo_payload organizza le stesse informazioni in un dizionario Python con timestamp precisi.

    #Riepilogo dei Metodi

    MetodoResponsabilità
    __init__Configura il contesto del builder (ID, file, flag e preferenze di formato).
    format_metadata_payloadGestisce la visualizzazione dei dizionari extra, convertendoli in stringhe o JSON indentato.
    build_messageGenera la stringa finale formattata per la visualizzazione nei log della console o nei file di testo.
    build_mongo_payloadCrea un dizionario strutturato con data/ora per l'inserimento nei database.

    #Architettura e Spunti

    • Separazione delle Responsabilità: La classe separa la logica di formattazione dalla logica di trasporto (invio al database). Non "logga" nulla, "costruisce" soltanto il payload.
    • Tracciabilità (Osservabilità): L'uso di log_id permette di correlare diverse voci di log che appartengono alla stessa richiesta o allo stesso processo.
    • Resilienza: Il metodo di formattazione ha un blocco try/except per garantire che, anche se la serializzazione JSON fallisce, il log non faccia crollare l'applicazione, ripiegando su una stringa semplice.

    #Dettaglio della Classe

    #Classe PayloadBuilder

    Descrizione

    Responsabile di centralizzare la composizione dei messaggi di log, la gestione dei metadati e l'organizzazione delle informazioni di contesto per garantire la standardizzazione su uscite diverse (console e database).

    Argomenti

    • log_id (str, opzionale): Identificatore univoco della transazione o del processo.
    • flag (str, opzionale): Tag per la categorizzazione (es: "SISTEMA_PAGAMENTO").
    • file_name (str, opzionale): Nome del file Python in cui è avvenuto il log.
    • format_metadata (bool): Se True, formatta i dizionari di metadati con indentazione JSON.

    #Metodi

    #1. format_metadata_payload()

    Descrizione

    Formatta il dizionario dei metadati in una rappresentazione stringa.

    Argomenti

    • metadata (Dict[str, Any]): Dati aggiuntivi da includere nel log.
    • show_metadata (bool): Flag che autorizza o meno l'inclusione dei dati nell'output.

    Valori di ritorno

    • Optional[str]: Stringa formattata oppure None se i dati non devono essere mostrati.

    Raises

    • Nessuna: Cattura le eccezioni internamente e restituisce la rappresentazione stringa grezza (str(metadata)) in caso di errore.

    Esempi

    # Com format_metadata=True na classe
builder.format_metadata_payload({"status": 200}, True)
# Retorna: "\n{\n    "status": 200\n}\n"`

    #2. build_message()

    Descrizione

    Assembla la stringa di log finale, unendo i componenti con un separatore verticale (|).

    Argomenti

    • func_name (str): Nome della funzione di origine.
    • message (str): Testo esplicativo del log.
    • metadata (Dict): Dati extra.
    • show_metadata (bool): Se i dati extra devono comparire in questo messaggio.

    Valori di ritorno

    • str: Riga di log completa e formattata.

    Raises

    • ValueError: Se non viene fornito alcun parametro (messaggio vuoto).

    Esempi

    builder.build_message("process_data", "Sucesso", {"items": 5}, True)
# Retorna: 'process_data() | Sucesso | metadata={'items': 5} | log_id=...'

    #3. build_mongo_payload()

    Descrizione

    Prepara un oggetto pronto per essere inserito nelle collezioni di MongoDB o in database simili.

    Argomenti

    • level (str): Livello del log (DEBUG, INFO, ERROR, ecc).
    • func_name (str): Funzione di origine.
    • message (str): Contenuto del log.
    • metadata (Dict): Dati strutturati.

    Valori di ritorno

    • Dict[str, Any]: Dizionario contenente campi standardizzati e timestamp.

    Raises

    • ValueError: Se il livello (level) non viene indicato.

    Esempi

    builder.build_mongo_payload("error", "save_user", "Falha de conexão", {"db": "prod"})
# Retorna: {'log_id': '...', 'level': 'ERROR', 'time': '2026-03-18...', ...}
