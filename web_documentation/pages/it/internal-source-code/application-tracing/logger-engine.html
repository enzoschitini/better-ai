Logger Engine

Questa è una documentazione dettagliata e didattica della classe LoggerEngine, progettata per essere il nucleo della tracciabilità e del monitoraggio delle applicazioni Python.

In questa pagina

    #Panoramica

    LoggerEngine non è un semplice formattatore di messaggi; è un orchestratore di telemetria. La sua funzione principale è centralizzare la cattura degli eventi di sistema e decidere, in base a configurazioni dinamiche (variabili d'ambiente o parametri di istanza), dove questi dati devono andare: console, file locali o un database NoSQL (MongoDB).

    L'obiettivo principale è garantire che lo sviluppatore abbia log strutturati. Invece di semplici righe di testo, la classe trasforma ogni evento in un oggetto dati ricco, facilitando gli audit e la ricerca degli errori negli ambienti di produzione.

    #Flusso di Esecuzione

    Per capire come opera la classe, immagina il seguente percorso compiuto da un'informazione:

    1. Chiamata del Metodo log(): L'utente invia il messaggio, il livello (INFO, ERROR, ecc.) e i metadati.
    2. Risoluzione delle Configurazioni: Il motore verifica se deve seguire la configurazione globale della classe o se c'è stata un'istruzione specifica per quella chiamata (es: forzare il salvataggio in MongoDB solo per un errore critico).
    3. Costruzione del Payload: I dati grezzi vengono inviati a un "Builder" che standardizza il formato (aggiunge timestamp, ID univoci e formatta il JSON).
    4. Configurazione del Logger: La classe prepara gli "Handler" (le uscite). Se save_logs è True, apre un canale verso il file; se deve mostrare sulla console, definisce il livello di verbosità.
    5. Emissione e Persistenza: Il messaggio viene mostrato a schermo e, contemporaneamente, il payload strutturato viene inviato a MongoDB.

    #Riepilogo dei Metodi

    MetodoResponsabilità
    _get_env_boolLegge le variabili d'ambiente (OS) e le converte in booleano in modo sicuro.
    _resolve_configDecide quali flag (salvare, mostrare, rendere persistente) verranno usate nell'esecuzione corrente.
    _build_payloadsTrasforma gli argomenti in messaggi leggibili e oggetti JSON strutturati.
    _get_loggerConfigura la libreria nativa logging di Python (Handler e Formatter).
    _emit_logEsegue l'invio finale del messaggio alle uscite di testo.
    _save_to_mongoGestisce la comunicazione e l'inserimento dei log nel database.
    logPunto di ingresso unico. Orchestra l'esecuzione di tutti i metodi precedenti.

    #Architettura e Spunti

    • Configurazione Ibrida: La classe utilizza uno schema di priorità: Variável de Ambiente > Argumento do Método > Valor Padrão da Instância. Questo permette di cambiare il comportamento del log senza modificare il codice, cambiando soltanto l'ambiente.
    • Disaccoppiamento dei Payload: Nota che la classe distingue il "messaggio di testo" (che gli umani leggono sulla console) dal "payload di dati" (che le macchine elaborano in MongoDB).
    • Tracciabilità Univoca: L'uso di un log_id generato automaticamente permette di tracciare una specifica transazione attraverso più file o collezioni del database.

    #Dettaglio Tecnico

    #Classe LoggerEngine

    Descrizione
    Gestore centralizzato di log strutturati. Permette il controllo dinamico della verbosità e la persistenza dei dati in più destinazioni, garantendo la standardizzazione in tutta l'applicazione.

    Argomenti

    • log_id (str): Identificatore univoco della transazione.
    • flag (str): Identificatore dell'origine (es: "AuthService").
    • file_name (str): Nome del modulo Python di origine.
    • log_file_name (str): Prefisso del file di log locale.
    • show_info_logs (bool): Abilita/Disabilita il livello INFO sulla console.
    • show_metadata (bool): Definisce se i dati extra compaiono nel testo del log.
    • save_logs (bool): Abilita la scrittura su file .log.
    • save_mongo (bool): Abilita la persistenza in MongoDB.
    • format_metadata (bool): Applica una formattazione visiva ai metadati.

    #1. Metodo log()

    Descrizione
    Metodo principale e pubblico. Funge da "direttore d'orchestra" della classe: riceve i dati e attiva i metodi privati nell'ordine corretto per elaborare il log.

    Argomenti

    • level (str): Livello di gravità (es: "INFO", "WARNING", "ERROR", "CRITICAL").
    • func_name (str, opzionale): Nome della funzione in cui è stato generato il log.
    • message (str, opzionale): Testo esplicativo dell'evento.
    • metadata (dict, opzionale): Dizionario con dati tecnici aggiuntivi.
    • save_logs / save_mongo / show_info_logs / show_metadata (bool, opzionale): Parametri per sovrascrivere il comportamento predefinito dell'istanza solo per questo log.

    Valori di ritorno

    • dict: Restituisce il payload completo che è stato generato e/o reso persistente.

    Raises

    • AttributeError: Se il level indicato non è un livello di log valido.
    • ConnectionError: Se il salvataggio in MongoDB fallisce.

    Esempi

    logger = LoggerEngine(flag="API_GATEWAY", save_mongo=True)

# Exemplo simples
logger.log(level="INFO", message="Servidor iniciado na porta 8080")

# Exemplo complexo com metadados e sobrescrita
logger.log(
    level="ERROR",
    func_name="process_payment",
    message="Falha na transação",
    metadata={"user_id": 123, "error_code": "ST-404"},
    save_logs=True # Força salvar em arquivo este erro específico
)

    #2. Metodo _get_env_bool()

    Descrizione
    Utilità interna per catturare in modo sicuro le configurazioni del sistema operativo, trattando stringhe come "true", "1" o "yes" come valori booleani veri.

    Argomenti

    • env_name (str): Il nome della chiave della variabile d'ambiente.
    • default (bool): Il valore di ritorno nel caso in cui la variabile non sia definita.

    Valori di ritorno

    • bool: Lo stato logico risolto.

    Raises

    • KeyError: Se il valore presente nella variabile d'ambiente non è valido (non convertibile in booleano).

    Esempi

    # Se no terminal: export SHOW_INFO_LOGS=True
val = engine._get_env_bool("SHOW_INFO_LOGS", False)
# val será True

    #3. Metodo _resolve_config()

    Descrizione
    Questo metodo agisce come il cervello decisionale della classe. Confronta le configurazioni globali (definite quando si istanzia la classe) con quelle locali (passate al momento del log). Se un parametro viene inviato come None, assume il valore predefinito dell'istanza.

    Argomenti

    • save_logs (bool/None): Volontà di salvare su file per questo evento.
    • save_mongo (bool/None): Volontà di rendere persistente nel database per questo evento.
    • show_info_logs (bool/None): Volontà di mostrare il livello INFO sulla console.
    • show_metadata (bool/None): Volontà di mostrare i metadati sulla console.

    Valori di ritorno

    • dict: Un dizionario con le chiavi e i loro valori booleani finali (Es: {'save_logs': True, ...}).

    Esempi

    # Instância configurada para NÃO salvar nada
engine = LoggerEngine(save_logs=False)

# Chamada forçando o salvamento
config = engine._resolve_config(save_logs=True, save_mongo=None, ...)
# config['save_logs'] será True (sobrescrita)

    #4. Metodo _build_payloads()

    Descrizione
    Responsabile della standardizzazione dei dati. Separa il "messaggio per gli umani" (stringa formattata) dal "payload per le macchine" (dizionario strutturato). Utilizza internamente una classe ausiliaria (PayloadBuilder) per garantire che tutti i log del sistema abbiano lo stesso aspetto.

    Argomenti

    • level (str): Livello del log.
    • func_name (str): Nome della funzione di origine.
    • message (str): Testo del messaggio.
    • metadata (dict): Dati extra.
    • show_metadata (bool): Definisce se il dizionario dei metadati deve essere inserito nella stringa di testo.

    Valori di ritorno

    • tuple: (display_message: str, mongo_payload: dict)

    #5. Metodo _get_logger()

    Descrizione
    Configura l'infrastruttura della Python Standard Library (logging). Crea l'oggetto che "parla" davvero con la console e con il file system, definendo colori, formati di data e il file verso cui inviare il testo.

    Argomenti

    • save_logs (bool): Se True, aggiunge un FileHandler.
    • show_info_logs (bool): Definisce il level minimo del logger (DEBUG, INFO o WARNING).

    Valori di ritorno

    • logging.Logger: L'oggetto logger pronto all'uso.

    #6. Metodo _emit_log()

    Descrizione
    È il grilletto finale. Dopo che tutto è configurato e il messaggio è formattato, questo metodo identifica il livello richiesto (info, error, debug) e invia il comando all'oggetto logger.

    Argomenti

    • logger (logging.Logger): L'istanza configurata nel metodo precedente.
    • level (str): La gravità.
    • message (str): Il messaggio finale già formattato.

    Raises

    • AttributeError: Se provi a usare un livello che non esiste (es: logger.log(level="BATATA")).

    #7. Metodo _save_to_mongo()

    Descrizione
    Esegue la persistenza persistente. Prende il payload strutturato e lo invia a una collezione in MongoDB. Questo è cruciale per le dashboard future (come Grafana o Kibana).

    Argomenti

    • mongo_metadata (dict): Il payload completo generato da _build_payloads.

    Valori di ritorno

    • str: L'ID del documento inserito nel database.

    Raises

    • ConnectionError: Se il database è fuori servizio o le credenziali sono errate.

    #Riepilogo del Ciclo di Vita del Log

    Per visualizzare come interagiscono questi metodi, immagina questa sequenza:

    1. User chiama log().
    2. log() chiama _resolve_config() per conoscere le regole.
    3. log() chiama _build_payloads() per preparare i dati.
    4. log() chiama _get_logger() per preparare l'uscita.
    5. log() chiama _emit_log() per stampare a schermo/su file.
    6. log() chiama _save_to_mongo() per salvare nel database.
