Storage / Supabase

Storage Menager

Documentazione dell'integrazione di BetterAI con Supabase Storage: come configurare i bucket e inviare, leggere, elencare e rimuovere file, anche insieme a un record di tabella.

In questa pagina

    #Panoramica

    La gestione dei file nei bucket di Supabase avviene tramite la stessa integrazione delle tabelle, in src/database/supabase_integration/. I flussi del progetto non usano direttamente l'SDK supabase: chiedono l'integrazione e usano sb.storage.

    • get_supabase().storage: la classe dei file (FileStore) con upload, download, download_to, signed_url, public_url, exists, list, delete e delete_prefix.
    • BytesSource, PathSource, StreamSource: le tre forme per fornire il contenuto da inviare.
    • UploadOptions: bucket, cartella, percorso esplicito, politica di collisione, tipo di contenuto e metadati.
    • StorageRepository (src/storage/storage_repository.py): wrapper del progetto per inviare immagini e ottenere l'URL pubblico, usato dalla generazione di immagini.

    Tutte le operazioni validano l'input prima di andare in rete (bucket consentito, dimensione, estensione, tipo dichiarato e contenuto reale) e sollevano eccezioni di dominio invece di restituire None.

    #Flusso di upload

    1. Bucket: UploadOptions.bucket (o SBX_BUCKET_DEFAULT) viene risolto e verificato rispetto alla allowlist dei bucket.
    2. Validazione: dimensione (vuoto e oltre il tetto vengono rifiutati), estensione, tipo dichiarato e contenuto reale (magic bytes) devono concordare.
    3. Percorso: path esplicito, oppure generato come <folder>/AAAA/MM/<uuid><ext>.
    4. Invio: upload standard oppure, oltre SBX_STORAGE_RESUMABLE_THRESHOLD_BYTES (6 MiB), upload resumable (TUS), letto in stream.
    5. Collisione: se il percorso esiste già, vale la CollisionPolicy (REJECT, VERSION o OVERWRITE).
    6. Risultato: uno StoredFile con bucket, path, size, content_type, original_name, upload_mode e metadata.

    #Configurazione

    La configurazione proviene dalle variabili d'ambiente SBX_*. Quelle usate dai file sono:

    VariabileDescrizione
    SBX_URLURL https del progetto Supabase (obbligatoria)
    SBX_SECRET_KEYChiave secret del backend (obbligatoria; mai nel frontend)
    SBX_BUCKET_DEFAULTBucket predefinito (es.: images)
    SBX_BUCKETS_ALLOWLISTBucket consentiti, separati da virgola (obbligatoria in prod)
    SBX_BUCKETS_PUBLICBucket pubblici; solo per questi public_url funziona
    SBX_STORAGE_MAX_FILE_BYTESDimensione massima del file (50 MiB)
    SBX_STORAGE_ALLOWED_MIMETipi MIME consentiti; accetta image/*; vuoto accetta qualsiasi
    SBX_STORAGE_SIGNED_URL_TTL_SECONDSValidità predefinita dell'URL firmato (300)
    SBX_STORAGE_SIGNED_URL_MAX_TTL_SECONDSTetto della validità dell'URL firmato (3600)
    SBX_STORAGE_RESUMABLE_THRESHOLD_BYTESDimensione oltre la quale l'upload diventa resumable (6 MiB)
    SBX_STORAGE_MEMORY_CAP_BYTESTetto di memoria per BytesSource e download (32 MiB)
    SBX_STORAGE_UPLOAD_TIMEOUT_SECONDSTimeout dell'upload in secondi (120)
    SBX_STORAGE_MAX_CONCURRENT_TRANSFERSTrasferimenti simultanei (4)

    Bucket pubblico. Per generare l'URL pubblico delle immagini, il bucket deve essere in SBX_BUCKETS_PUBLIC (per esempio SBX_BUCKET_DEFAULT=images, SBX_BUCKETS_PUBLIC=images, SBX_BUCKETS_ALLOWLIST=images). In homol e prod il .env da file è vietato. L'elenco completo è in src/database/supabase_integration/.env.example.

    #Upload

    from src.database.supabase_provider import get_supabase
from src.database.supabase_integration import BytesSource, PathSource, StreamSource, UploadOptions, CollisionPolicy

storage = get_supabase().storage

st = storage.upload(
    BytesSource(b"content", filename="note.txt", content_type="text/plain"),
    UploadOptions(folder="docs"),  # Percorso generato: docs/AAAA/MM/<uuid>.txt
)
print(st.bucket, st.path, st.size, st.upload_mode, st.content_type, st.original_name)

big = storage.upload(
    PathSource("video.mp4", content_type="video/mp4"),  # Letto in stream; oltre 6 MiB diventa resumable (TUS)
    UploadOptions(folder="videos"),
)

with open("report.pdf", "rb") as f:
    storage.upload(StreamSource(f, size=None, filename="report.pdf", content_type="application/pdf"))  # Stream, per esempio l'UploadFile di FastAPI

storage.upload(
    BytesSource(b"v2", filename="a.txt", content_type="text/plain"),
    UploadOptions(path=st.path, collision=CollisionPolicy.VERSION),  # Collisione: scrive in un percorso nuovo (-v2)
)

    #Sorgenti di dati

    ClasseCampiNote
    BytesSourcedata, filename, content_typeIn memoria; oltre SBX_STORAGE_MEMORY_CAP_BYTES solleva ValidationError (usa PathSource o StreamSource).
    PathSourcepath, filename, content_typeLegge dal disco in stream; filename predefinito è il nome del file; file inesistente solleva ValidationError.
    StreamSourcestream, size, filename, content_type, restartableCon size e stream che permette seek, viene riletto in caso di retry; senza size viene copiato in un file temporaneo (i byte vengono contati e il tetto verificato).

    #UploadOptions

    CampoEffetto
    bucketNone usa SBX_BUCKET_DEFAULT; deve essere nella allowlist.
    folderSottocartella logica (validata). Percorso generato: <folder>/AAAA/MM/<uuid><ext>.
    pathPercorso esplicito, che sostituisce la denominazione automatica ed è sempre validato.
    collisionREJECT (predefinito: FileAlreadyExistsError), VERSION (scrive in nome-v2.ext, -v3...) oppure OVERWRITE (sovrascrive, solo esplicito).
    content_typeTipo MIME dichiarato, confrontato con l'estensione e il contenuto.
    metadataMetadati str verso str (fino a 50 voci); l'integrazione aggiunge original_name.
    cache_control_secondsNone usa SBX_STORAGE_CACHE_CONTROL_SECONDS.
    correlation_idIdentificatore per collegare i log dell'operazione.

    Il tipo di contenuto viene scelto così: contenuto rilevato (se specifico), poi quello dichiarato, poi l'estensione, infine application/octet-stream. Estensione, tipo dichiarato e contenuto devono concordare, altrimenti solleva ValidationError. Nei bucket pubblici i tipi attivi (.html, .svg, .js, eseguibili) vengono rifiutati.

    I percorsi degli oggetti accettano solo ASCII [A-Za-z0-9._-], senza accenti né spazi, senza segmenti che iniziano con un punto e fino a 8 livelli. Nel percorso generato, il nome originale dell'utente va come metadato (original_name), non nel percorso.

    #Upload di immagini nel progetto

    La generazione di immagini scrive i file tramite lo StorageRepository, che usa l'integrazione: costruisce il percorso <base_path>/<file_name>, invia i byte e restituisce l'URL pubblico. Se l'upload fallisce, solleva RuntimeError con la causa originale in __cause__.

    from src.storage.storage_repository import StorageRepository

repository = StorageRepository(base_path="image_generations", bucket_name="images")

url = repository.upload_to_supabase(file_name="example_image.png", byte_data=image_bytes)
print(url)  # URL pubblico del file nel bucket

    #Lettura

    data = storage.download(st.path)  # bytes, limitato dal tetto di memoria (32 MiB)
storage.download_to(big.path, "out/video.mp4")  # Stream diretto su disco, per file grandi
url = storage.signed_url(st.path, ttl_seconds=300)  # URL firmato; tetto 3600 s, oltre ValidationError
pub = storage.public_url(st.path, bucket="images")  # Solo per bucket in SBX_BUCKETS_PUBLIC
found = storage.exists(st.path)
page = storage.list(prefix="docs", limit=100)  # Page[ObjectInfo]
for o in page.items:
    print(o.path, o.size, o.content_type, o.updated_at, o.is_folder)

    exists restituisce False anche con 401 e 403 (limitazione dell'SDK): un problema di permessi può sembrare "non esiste".

    #Rimozione

    rep = storage.delete([st.path, big.path])  # Idempotente; report per percorso
print(rep.requested, rep.removed, rep.failed)  # failed: {percorso: motivo}
storage.delete_prefix("docs/2026/11")  # DISTRUTTIVO: cancella tutto sotto il prefisso, ricorsivamente

    Gli errori parziali in delete non sollevano eccezioni: controlla rep.failed. delete_prefix è distruttivo e ricorsivo (profondità massima 16); il prefisso vuoto è vietato.

    #Tabella dei metodi

    MetodoRitornoDescrizione breve
    upload(source, options=None)StoredFileValida e invia il file; upload_mode è standard o resumable.
    download(path, bucket=None)bytesScarica in memoria; rifiuta oggetti oltre il tetto (use download_to).
    download_to(path, destination, bucket=None)PathScarica in stream su disco e crea le cartelle padre.
    signed_url(path, bucket=None, ttl_seconds=None)strURL temporaneo; non viene mai registrato nei log.
    public_url(path, bucket=None)strURL pubblico, solo per bucket in SBX_BUCKETS_PUBLIC; costruito localmente, senza rete.
    exists(path, bucket=None)boolIndica se l'oggetto esiste.
    list(prefix="", bucket=None, limit=None, offset=0)Page[ObjectInfo]Elenca gli oggetti; le cartelle arrivano con is_folder=True.
    delete(paths, bucket=None)DeleteReportRimuove in blocchi; idempotente; gli errori vanno in failed.
    delete_prefix(prefix, bucket=None)DeleteReportRimuove tutto sotto il prefisso, ricorsivamente.

    #File e record insieme

    Quando il file deve essere scritto insieme a un record di tabella, usa le operazioni combinate della facciata. Seguono un ordine fisso e compensano in caso di errore: se il record fallisce dopo l'upload, il file viene cancellato. Le tabelle sono descritte nella pagina Supabase Database.

    sb = get_supabase()

r = sb.save_file_with_record(
    "sbx_test_items",
    BytesSource(b"content", filename="contract.txt", content_type="text/plain"),
    lambda f: {"name": "contract", "bucket": f.bucket, "path": f.path},  # Costruisce il record dal file scritto
    UploadOptions(folder="contracts"),
)
r.raise_if_failed()  # Solleva lo stesso errore originale, se c'è stato un errore
print(r.status.value, r.record["id"])  # completa, parziale o fallita

sb.replace_file_in_record(
    "sbx_test_items", r.record["id"],
    BytesSource(b"v2", filename="contract.txt", content_type="text/plain"),
    lambda f: {"bucket": f.bucket, "path": f.path},
    old_ref=(r.stored_file.bucket, r.stored_file.path),  # Il file vecchio viene cancellato per ultimo
)

sb.delete_record_and_file("sbx_test_items", r.record["id"], (r.stored_file.bucket, r.stored_file.path))  # Prima il record, poi il file
    statusSignificatoorphan_possible
    completaTutti i passi sono stati completati.False
    falhouNulla è rimasto (errore prima di scrivere, o compensazione riuscita).False
    parcialÈ rimasto qualcosa: file orfano o file vecchio non cancellato. Il log riporta orfao_possivel=true con bucket e path.True

    raise_if_failed() solleva anche nello stato parcial, anche quando il record è stato aggiornato. Leggi r.status prima di decidere.

    #Gestione degli errori

    EccezioneQuando
    ValidationErrorBucket fuori dalla allowlist, file vuoto, tipo discordante o non consentito, percorso non valido, URL firmato oltre il tetto, bucket non pubblico in public_url.
    FileTooLargeErrorFile oltre SBX_STORAGE_MAX_FILE_BYTES o risposta 413 di Storage.
    FileAlreadyExistsErrorIl percorso esiste già con CollisionPolicy.REJECT.
    FileNotFoundInStorageErrorOggetto inesistente (Storage usa 404 anche per "senza permesso").
    PermissionDeniedError, AuthenticationErrorLa policy del bucket ha negato l'accesso; chiave non valida.
    UploadError, DownloadErrorErrore di storage non classificato.
    OperationTimeoutError, ServiceUnavailableError, RateLimitErrorErrori transitori (retryable=True).
     
    try:
    storage.upload(BytesSource(data, filename="a.png"), UploadOptions(path="images/a.png"))
except FileAlreadyExistsError:
    ...  # Il percorso esiste già
except SupabaseIntegrationError as e:  # Qualsiasi errore dell'integrazione
    print(e.retryable, e.outcome_unknown, e.correlation_id)

    #Architettura e insight

    • Upload resumable: oltre SBX_STORAGE_RESUMABLE_THRESHOLD_BYTES l'invio usa il protocollo TUS a chunk, senza caricare l'intero file in memoria.
    • Retry sicuro: solo OVERWRITE viene ripetuto dall'esecutore. Con REJECT e VERSION un timeout diventa outcome_unknown=True e l'oggetto potrebbe essere stato scritto: controlla con exists.
    • Nomi sicuri: il percorso generato non usa mai il nome dell'utente, evitando collisioni e caratteri non validi.
    • Senza bloccare l'event loop: in FastAPI usa create_async_integration; await asb.upload(...) gira in un thread.
    • Segreti protetti: la chiave SBX_SECRET_KEY e gli URL firmati non compaiono mai nei log o nei messaggi di errore.
