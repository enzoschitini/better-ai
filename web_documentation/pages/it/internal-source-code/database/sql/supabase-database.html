Supabase Database

Documentazione dell'integrazione di BetterAI con le tabelle di Supabase: come ottenere l'integrazione, dichiarare le tabelle ed eseguire CRUD, query, paginazione e operazioni in blocco.

In questa pagina

    #Panoramica

    L'accesso alle tabelle di Supabase avviene tramite un'unica integrazione, che si trova in src/database/supabase_integration/. I flussi del progetto non creano client dell'SDK supabase né scrivono SQL: chiedono l'integrazione al punto di composizione e operano su repository di tabella.

    • get_supabase() (src/database/supabase_provider.py): restituisce l'integrazione condivisa del processo, creata alla prima chiamata a partire dalle variabili SBX_*.
    • TableDescriptor: descrive una tabella (nome, chiave primaria, colonne consentite, colonne gestite dal server, modello).
    • sb.tables.table("nome"): restituisce il TableRepository con le operazioni di CRUD, query, paginazione e blocco.
    • Query, Condition, FilterGroup, Sort, PageRequest: oggetti di query indipendenti dall'SDK.

    L'integrazione parla con Supabase tramite l'API REST (PostgREST). Non c'è esecuzione di SQL grezzo: filtri, ordinamenti e scritture sono descritti con gli oggetti di query e validati prima di andare in rete.

    #Flusso di esecuzione

    Il flusso di un'operazione su tabella segue questi passi:

    1. Configurazione: get_supabase() legge le variabili SBX_*, valida tutto in una volta e fallisce subito, elencando solo i nomi mancanti o non validi.
    2. Registrazione: le tabelle dichiarate in _table_descriptors() vengono registrate alla creazione dell'integrazione.
    3. Repository: sb.tables.table("nome") restituisce il repository della tabella, purché sia registrata e consentita.
    4. Validazione: colonne, filtri e valori vengono validati prima della rete (ValidationError, MappingError).
    5. Esecuzione: la chiamata passa dall'esecutore di resilienza (timeout di budget e retry con backoff, solo su operazioni idempotenti).
    6. Risultato: la riga, la lista, la pagina o il risultato del blocco torna come dict (o come il model del descrittore); qualsiasi errore diventa un'eccezione di dominio (SupabaseIntegrationError e sottoclassi).

    #Configurazione

    La configurazione proviene dalle variabili d'ambiente SBX_*. Quelle usate dalle tabelle sono:

    VariabileDescrizione
    SBX_URLURL https del progetto Supabase (obbligatoria)
    SBX_SECRET_KEYChiave secret del backend (obbligatoria; mai nel frontend)
    SBX_TABLES_ALLOWLISTTabelle consentite, separate da virgola (obbligatoria in prod)
    SBX_DB_SCHEMASchema Postgres (predefinito public)
    SBX_TABLES_DEFAULT_PAGE_SIZEDimensione di pagina predefinita (50)
    SBX_TABLES_MAX_PAGE_SIZETetto della dimensione di pagina (predefinito min(1000, server max rows))
    SBX_TABLES_BATCH_SIZEDimensione di ogni chunk nelle operazioni in blocco (500)
    SBX_TABLES_SERVER_MAX_ROWSmax-rows reale del progetto Supabase (1000)
    SBX_TABLES_QUERY_TIMEOUT_SECONDSTimeout delle query in secondi (10)
    SBX_TABLES_BATCH_TIMEOUT_SECONDSTimeout delle operazioni in blocco in secondi (60)

    Regole di ambiente. In homol e prod il file .env è vietato (usa le variabili della piattaforma) e prod richiede SBX_TABLES_ALLOWLIST. Una nuova tabella richiede un TableDescriptor e deve essere nella allowlist. L'elenco completo è in src/database/supabase_integration/.env.example.

    #Ottenere l'integrazione

    from src.database.supabase_provider import get_supabase

sb = get_supabase()  # Integrazione condivisa del processo
items = sb.tables.table("sbx_test_items")  # Repository della tabella

    Le tabelle usate dai flussi sono dichiarate in _table_descriptors(), in src/database/supabase_provider.py. Aggiungere una tabella significa aggiungere un descrittore, senza modificare altro codice esistente:

    from src.database.supabase_integration import TableDescriptor

def _table_descriptors():
    return (
        TableDescriptor(
            "sbx_test_items",
            columns=("id", "name", "qty", "created_at"),  # Allowlist di colonne
            server_managed_columns=("id", "created_at"),  # Compilate dal server
            sort_key="created_at",  # Abilita la paginazione keyset
        ),
    )

    #TableDescriptor

    CampoSignificato
    nameNome della tabella. Deve essere in SBX_TABLES_ALLOWLIST se esiste.
    schemaSchema Postgres (predefinito public).
    primary_keyColonna della chiave primaria, usata da get_by_id, update, delete e nello spareggio dell'ordinamento (predefinito id).
    modelNone restituisce dict; accetta anche dataclass o classi in stile Pydantic.
    server_managed_columnsColonne che il server compila (id, created_at). Non vengono inviate nell'insert quando None e vengono rifiutate nell'update.
    columnsAllowlist di colonne per filtro, ordinamento, scrittura e selezione. None non limita. Deve contenere la chiave primaria e la sort_key.
    sort_keyColonna stabile e non nulla che abilita la paginazione keyset (es.: created_at).

    #Create

    novo = items.insert({"name": "Ana", "qty": 1})  # Restituisce la riga scritta, già con id e created_at
print(novo["id"])

lote = items.insert_many(  # Blocco: un risultato per elemento
    [{"name": f"item-{i}", "qty": i} for i in range(25)],
    BatchOptions(batch_size=10, mode="continue"),
)
print(lote.total, lote.succeeded, lote.failed, lote.all_ok, lote.stopped_early)
for it in lote.items:
    if not it.ok:
        print("failed item", it.index, type(it.error).__name__)

    #Read

    um = items.get_by_id(novo["id"])  # RecordNotFoundError se non esiste

achados = items.find(Query.where(Condition("name", Op.ILIKE, "an%")))  # Lista vuota se nulla corrisponde
iguais = items.find(Query.eq("qty", 5))

q = Query(
    filter=FilterGroup(items=(
        Condition("qty", Op.GTE, 5),
        FilterGroup(items=(Condition("qty", Op.EQ, 7), Condition("qty", Op.EQ, 9)), logic="or"),
    )),  # qty >= 5 AND (qty = 7 OR qty = 9)
    sorts=(Sort("name"),),
    columns=("id", "name", "qty"),  # Proiezione opzionale
)
pag = items.list(q, PageRequest(limit=10, offset=0, include_count=True))
print(pag.items, pag.total, pag.has_more)

for linha in items.iterate(q, page_size=100):  # Scansione di tabella grande, una pagina alla volta
    ...

    find() carica in memoria tutte le righe che corrispondono. Per tabelle grandi usa iterate().

    #Update

    atual = items.update(novo["id"], {"qty": 5})  # RecordNotFoundError se non esiste
n = items.update_where(Condition("name", Op.LIKE, "item-%"), {"qty": 0})  # Restituisce il numero di righe interessate
items.upsert({"id": novo["id"], "name": "Ana", "qty": 999}, on_conflict="id")  # Inserisce o aggiorna
items.upsert_many([{"id": 1, "name": "A"}, {"id": 2, "name": "B"}], on_conflict="id")

    #Delete

    r = items.delete(novo["id"])  # Idempotente
print(r.removed, r.removed_count)  # removed=False se non esisteva già
items.delete_where(Condition("name", Op.LIKE, "item-%"))  # Il filtro vuoto viene rifiutato (ValidationError)

    update_where e delete_where rifiutano il filtro vuoto (ValidationError). È la protezione contro la modifica o la cancellazione dell'intera tabella.

    #Query

    Query ha filter, sorts e columns. Scorciatoie: Query.where(*conditions) (AND tra le condizioni) e Query.eq(colonna, valore). Un FilterGroup combina Condition o altri gruppi con logic="and" oppure "or" (profondità massima 8).

    OperatoreSignificatoRegola del valore
    EQ, NEQ, GT, GTE, LT, LTEConfrontiScalare non nullo (usa IS_NULL/NOT_NULL per i nulli)
    INAppartiene aLista, tupla o insieme, fino a 1000 elementi
    LIKE, ILIKEPattern con %Testo
    IS_NULL, NOT_NULLNullo / non nulloIl valore viene ignorato
    CONTAINS@> su jsonb o arrayLista, dict o testo

    Valori accettati nelle scritture: str, int, bool, float finito, Decimal (inviato come testo), datetime con fuso orario (convertito in UTC), date, time, UUID, Enum, dict, list, tuple e set. Qualsiasi altro tipo solleva MappingError.

    #Paginazione

    PageRequest(limit=None, offset=0, cursor=None, include_count=False) richiede una pagina e Page restituisce items, limit, offset, next_cursor, total e has_more. Senza limit vale SBX_TABLES_DEFAULT_PAGE_SIZE; chiedere più del tetto effettivo riduce il valore con un avviso, senza errore.

    Offset (predefinito)Keyset (opzionale)
    QuandoPagine superficiali o salto alla pagina NScansione di tabelle grandi e pagine profonde
    RichiedeNientesort_key nel descrittore e ordinamento compatibile
    CostoCresce con l'offsetCostante
    StabilitàPuò ripetere o saltare righe se i dati cambianoStabile
     
    from src.database.supabase_integration.tables import KEYSET_START

cursor = KEYSET_START  # Apre la catena di pagine
while cursor:
    pag = items.list(Query(), PageRequest(limit=100, cursor=cursor))
    for linha in pag.items:
        ...
    cursor = pag.next_cursor  # None nell'ultima pagina

    Il cursore è opaco e firmato dalla query: usarlo con un altro filtro o direzione di ordinamento solleva ValidationError.

    #Operazioni in blocco

    insert_many e upsert_many ricevono BatchOptions(batch_size=None, mode="continue"). Ogni chunk è una richiesta atomica su Postgres; non c'è atomicità tra i chunk. L'intero blocco viene validato prima di qualsiasi invio.

    • mode="continue": un chunk che fallisce per dato o conflitto viene diviso a metà fino a isolare gli elementi errati; il resto viene scritto.
    • mode="stop": si ferma al primo chunk con errore e imposta stopped_early=True se resta parte del blocco.
    • BatchResult ha items (lista di ItemOutcome con index, ok, entity, error), stopped_early e le proprietà total, succeeded, failed e all_ok.

    #Entità tipizzate

    Per impostazione predefinita le righe sono dict. Per lavorare con dataclass o classi in stile Pydantic, indica model nel descrittore. insert e upsert accettano il modello o dict; le letture restituiscono il modello; update(id, {...}) riceve sempre un dict di modifiche.

    from dataclasses import dataclass
from datetime import datetime
from typing import Optional
from uuid import UUID

@dataclass
class Item:
    id: UUID
    name: str
    qty: int = 0
    created_at: Optional[datetime] = None

TableDescriptor("sbx_test_items", model=Item, server_managed_columns=("id", "created_at"))

novo = items.insert(Item(id=None, name="Ana", qty=1))  # id=None viene omesso (colonna del server)
outro = items.get_by_id(novo.id)  # Le letture restituiscono Item

    #Tabella dei metodi

    MetodoRitornoDescrizione breveRetry automatico
    get_by_id(id)entitàCerca per chiave primaria; RecordNotFoundError se non esiste.Sì
    find(query=None)listTutte le righe corrispondenti, in memoria; [] se nulla corrisponde.Sì
    list(query=None, page=None)PageUna pagina, per offset o keyset.Sì
    iterate(query=None, page_size=None)iteratoreScansione lazy, una pagina alla volta.Sì
    insert(entity)entitàScrive una riga e restituisce la riga scritta.No
    insert_many(entities, options=None)BatchResultScrive in blocco, con risultato per elemento.No
    update(id, changes)entitàAggiorna per chiave primaria; RecordNotFoundError se non esiste.Sì
    update_where(filter, changes)intAggiorna per filtro e restituisce le righe interessate; il filtro vuoto viene rifiutato.Sì
    upsert(entity, on_conflict=None)entitàInserisce o aggiorna; on_conflict predefinito è la chiave primaria.Sì
    upsert_many(entities, on_conflict=None, options=None)BatchResultUpsert in blocco.Sì
    delete(id)DeleteResultRimuove per chiave primaria; idempotente.Sì
    delete_where(filter)DeleteResultRimuove per filtro; il filtro vuoto viene rifiutato.Sì

    #Gestione degli errori

    Nessuna eccezione dell'SDK (supabase, postgrest, httpx) arriva al codice del progetto: tutto diventa SupabaseIntegrationError o una sottoclasse, con la causa originale in __cause__.

    EccezioneQuando
    ConfigurationErrorTabella non registrata o fuori dalla allowlist; tabella o colonna inesistente nel database.
    ValidationErrorInput non valido, rilevato prima della rete (colonna fuori dalla allowlist, filtro vuoto, valore non valido).
    MappingErrorErrore nella conversione di un valore o di una riga; cita tabella e campo, mai il valore.
    RecordNotFoundErrorget_by_id o update senza riga corrispondente.
    DuplicateRecordError, ReferenceViolationErrorViolazione di unicità (23505) o di chiave esterna (23503).
    DataErrorTipo, not-null o check rifiutati dal database.
    PermissionDeniedError, AuthenticationErrorUna policy RLS ha negato l'accesso; chiave o JWT non valido.
    OperationTimeoutError, ServiceUnavailableError, RateLimitErrorErrori transitori (retryable=True).
     
    try:
    items.get_by_id("00000000-0000-0000-0000-000000000000")
except RecordNotFoundError:
    ...  # 404 nell'endpoint
except ValidationError:
    ...  # 422: input non valido
except SupabaseIntegrationError as e:  # Qualsiasi errore dell'integrazione
    print(e.retryable, e.status, e.provider_code, e.attempts, e.outcome_unknown, e.correlation_id)

    insert e insert_many non vengono mai ripetuti automaticamente (non sono idempotenti). In caso di timeout l'errore porta outcome_unknown=True: controlla nel database prima di riprovare.

    #Architettura e insight

    • Lista di autorizzazioni: la tabella deve essere registrata e in SBX_TABLES_ALLOWLIST; le colonne di filtro, ordinamento e scrittura possono essere limitate da columns.
    • Segreti protetti: la chiave SBX_SECRET_KEY è un Secret che non compare mai in repr, log o messaggi di errore.
    • Resilienza: solo le operazioni idempotenti hanno retry con backoff e jitter, entro un budget di tempo (SBX_RETRY_*).
    • Senza bloccare l'event loop: in FastAPI usa create_async_integration, che esegue le chiamate in thread.
    • File e record insieme: per scrivere un file e il record che punta a esso, con compensazione in caso di errore, vedi la pagina Storage.
