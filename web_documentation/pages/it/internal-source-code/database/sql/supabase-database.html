Database / SQL

Supabase Database

Questa documentazione descrive in dettaglio l'architettura e il funzionamento del motore di persistenza dei dati creato per interagire con Supabase, utilizzando un approccio ibrido tra l'API REST (tramite il client ufficiale) e l'accesso diretto a PostgreSQL (tramite psycopg2).

In questa pagina

    #Panoramica

    Il codice implementa un livello di astrazione del database diviso in due responsabilità principali: Gestione della Connessione e Motore di Query (Query Engine).

    A differenza degli approcci che dipendono solo da librerie di alto livello, questo progetto punta sulle prestazioni e su un solido controllo transazionale, consentendo esecuzioni SQL pure, la manipolazione di JSONB e operazioni in blocco (bulk operations) in sicurezza.

    #Flusso di Esecuzione

    Il flusso di una normale operazione segue questi passi:

    1. Inizializzazione: SupabaseConnection carica le variabili d'ambiente e convalida le credenziali.
    2. Lazy Loading: La connessione al database PostgreSQL viene aperta solo nel momento in cui viene richiesta la prima query.
    3. Iniezione di Dipendenza: SupabaseQueryEngineer riceve il metodo di connessione.
    4. Esecuzione & Contesto: Il motore di query apre un cursore, esegue l'SQL e, in caso di successo, esegue il commit.
    5. Gestione degli Errori: Se qualcosa fallisce, viene attivato un rollback automatico per mantenere l'integrità dei dati.

    #Architettura e Insights

    • Resilienza (Auto-riconnessione): Il metodo get_connection esegue un "ping" (SELECT 1) sul database. Questo evita i comuni errori di "broken pipe" in ambienti serverless o quando la connessione resta inattiva per troppo tempo.
    • Risultati Tipizzati: L'uso di RealDictCursor trasforma le righe del database in dizionari Python nativi, facilitando l'uso nelle API e la manipolazione dei dati.
    • Sicurezza (SQL Injection): Il sistema utilizza la parametrizzazione (%s), delegando al driver la pulizia dei dati, il che previene gli attacchi di SQL injection.

    #Documentazione Dettagliata delle Classi

    #Classe SupabaseConnection

    Descrizione

    Gestisce il ciclo di vita della connessione all'ecosistema Supabase. Verifica che l'ambiente sia configurato correttamente e fornisce un'interfaccia per ottenere connessioni PostgreSQL stabili attraverso il protocollo TCP.

    Argomenti

    • Non ha argomenti di inizializzazione (legge direttamente da .env).

    #Metodi

    1. get_connection

    • Descrizione: Fornisce un'istanza di connessione psycopg2. Implementa il pattern Lazy Initialization.
    • Argomenti: Nessuno.
    • Valori di ritorno: psycopg2.extensions.connection
    • Raises: Exception se le credenziali sono errate o il database è inaccessibile.
    • Esempi: conn = connection.get_connection()

    #Classe SupabaseQueryEngineer

    Descrizione

    Il "cervello" delle operazioni sul database. Questa classe isola la complessità di SQL, gestendo cursori e transazioni (Commit/Rollback) in modo trasparente per lo sviluppatore.

    Argomenti

    • get_connection (Callable): Una funzione o un metodo che restituisca una connessione attiva.

    #Metodi

    1. select

    • Descrizione: Esegue query di ricerca dei dati.
    • Argomenti:
      • query (str): Comando SQL SELECT.
      • params (tuple, opzionale): Valori con cui sostituire i placeholder %s.
    • Valori di ritorno: List[Dict[str, Any]] - Una lista in cui ogni elemento è una riga della tabella.
    • Raises: Exception in caso di errore di sintassi SQL o errore di connessione.
    • Esempi: engine.select("SELECT * FROM users WHERE name = %s", ("Enzo",))

    2. execute

    • Descrizione: Esegue comandi che modificano lo stato del database (DDL o DML).
    • Argomenti:
      • query (str): Comando SQL (INSERT, UPDATE, DELETE, CREATE, ecc).
      • params (tuple, opzionale): Parametri della query.
    • Valori di ritorno: None
    • Raises: Exception con rollback automatico in caso di errore.
    • Esempi: engine.execute("UPDATE users SET name = %s", ("Novo Nome",))

    3. execute_many

    • Descrizione: Ottimizza l'inserimento o l'aggiornamento di grandi volumi di dati.
    • Argomenti:
      • query (str): Comando SQL parametrizzato.
      • params_list (List[tuple]): Lista contenente le tuple di parametri per ogni ripetizione.
    • Valori di ritorno: None
    • Raises: Exception se una qualsiasi delle operazioni fallisce (annulla l'intero lotto).
    • Esempi: engine.execute_many("INSERT INTO logs (msg) VALUES (%s)", [("Erro 1",), ("Erro 2",)])
