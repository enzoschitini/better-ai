Local Manage

Questa è una documentazione dettagliata e didattica della classe LocalManager, pensata per fare da guida sia agli utenti sia agli sviluppatori che vogliono comprendere la struttura di questo gestore di dati NoSQL locale.

In questa pagina

    #Panoramica

    LocalManager è una soluzione leggera ed efficiente per la persistenza dei dati in formato NoSQL, che usa il file system locale come archivio. Emula il comportamento dei database moderni (come MongoDB), organizzando le informazioni in una gerarchia di Databases (directory) e Collections (file JSON).

    È lo strumento ideale per:

    • Prototipazione rapida di applicazioni.
    • Archiviazione di configurazioni locali.
    • Ambienti di test in cui non si vuole configurare un server di database complesso.

    #Flusso di Esecuzione

    Il funzionamento della classe segue un ciclo prevedibile di gestione dell'I/O dei file:

    1. Inizializzazione: Il gestore verifica o crea la cartella radice (data).
    2. Mappatura: Quando viene richiesta un'operazione, risolve il percorso fisico: base/database/collection.json.
    3. Caricamento: Il file JSON viene letto e deserializzato in una lista di dizionari Python in memoria.
    4. Elaborazione: Filtri, inserimenti o aggiornamenti vengono applicati a questa lista.
    5. Persistenza: La lista risultante viene serializzata di nuovo nel file JSON, garantendo l'integrità dei dati.

    #Riepilogo dei Metodi

    MetodoDescrizione Breve
    save_payloadInserisce un nuovo record con ID univoco e timestamp.
    fetch_documentsFiltra e restituisce i documenti della collezione.
    update_documentsModifica i campi dei documenti esistenti in base ai filtri.
    delete_documentsRimuove record specifici o multipli dalla collezione.
    _get_collection_path(Interno) Risolve e crea il percorso delle directory per il database.
    _load_collection(Interno) Legge i dati dal file JSON con gestione degli errori.
    _save_collection(Interno) Scrive i dati su disco con un'indentazione leggibile.
    _match_filter(Interno) Confronta i documenti con i criteri di ricerca.

    #Architettura e Insights

    • Astrazione di ID e Tempo: Il sistema toglie allo sviluppatore l'onere di generare ID univoci (uuid4) e di registrare i momenti di creazione/aggiornamento, iniettando i metadati automaticamente.
    • Sicurezza di Scrittura: Usando os.makedirs(exist_ok=True), il codice evita i comuni errori di "directory non trovata" durante l'esecuzione.
    • Semplicità di Ricerca: Il filtraggio si basa sulla semplice uguaglianza, il che rende bassissima la curva di apprendimento per i nuovi utenti.

    #Classe LocalManager

    #Descrizione

    Gestore di persistenza locale che usa file JSON per simulare un database NoSQL. Organizza i dati in strutture di database e collezione all'interno del file system.

    #Argomenti

    • base_path (str): Nome della directory radice in cui verranno salvati tutti i dati. Predefinito: "data".

    #Metodi

    #1. save_payload

    Descrizione: Aggiunge un nuovo documento al database. Il metodo genera automaticamente un campo _id univoco e un campo _created_at.

    Argomenti:

    • database_name (str): Nome del database.
    • collection_name (str): Nome della collezione.
    • payload (dict): I dati che vuoi salvare.

    Valori di ritorno:

    • dict: Un dizionario contenente lo stato dell'operazione e l'ID generato.

    Raises:

    • Exception: Errori di permesso di scrittura o errore del file system.

    Esempio:

    manager.save_payload("loja", "produtos", {"nome": "Teclado", "preco": 150.0})

    #2. fetch_documents

    Descrizione: Recupera una lista di documenti che corrispondono ai criteri indicati.

    Argomenti:

    • database_name (str): Nome del database.
    • collection_name (str): Nome della collezione.
    • filter (dict, opzionale): Filtro di uguaglianza (es: {"status": "ativo"}).
    • limit (int): Limite massimo di risultati (0 per illimitato).

    Valori di ritorno:

    • List[Dict]: Lista dei documenti trovati.

    Raises:

    • json.JSONDecodeError: Se il file è corrotto.

    Esempio:

    manager.fetch_documents("loja", "produtos", filter={"nome": "Teclado"})

    #3. update_documents

    Descrizione: Individua i documenti tramite filtro e ne aggiorna i valori con un nuovo insieme di dati.

    Argomenti:

    • database_name (str): Nome del database.
    • collection_name (str): Nome della collezione.
    • filter (dict): Criterio per trovare i documenti da modificare.
    • new_values (dict): Nuovi campi e valori da inserire/modificare.
    • multi (bool): Se True, aggiorna tutti quelli trovati; se False, solo il primo.

    Valori di ritorno:

    • dict: Statistiche contenenti matched_count e modified_count.

    Raises:

    • IOError: Errore durante il salvataggio delle modifiche su disco.

    Esempio:

    manager.update_documents("loja", "produtos", {"nome": "Teclado"}, {"preco": 130.0})

    #4. delete_documents

    Descrizione: Rimuove dalla collezione i documenti che corrispondono al filtro passato.

    Argomenti:

    • database_name (str): Nome del database.
    • collection_name (str): Nome della collezione.
    • filter (dict): Criterio di selezione per la rimozione.
    • multi (bool): Se rimuovere tutti i corrispondenti o solo il primo.

    Valori di ritorno:

    • dict: Conferma con il numero di elementi eliminati (deleted_count).

    Raises:

    • Exception: Errori generici di accesso al file.

    Esempio:

    manager.delete_documents("loja", "produtos", {"status": "esgotado"}, multi=True)
