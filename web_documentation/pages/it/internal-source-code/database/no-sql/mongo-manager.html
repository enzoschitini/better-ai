Mongo Manager

Questa è una documentazione dettagliata e didattica della classe MongoDBManager, pensata per facilitare la comprensione degli sviluppatori che integreranno questo strumento nei propri progetti.

In questa pagina

    #Panoramica

    La classe MongoDBManager agisce come un Wrapper (o facilitatore) per la libreria pymongo. Il suo obiettivo principale è semplificare l'interazione con i database MongoDB, astraendo la complessità della gestione delle connessioni e garantendo che le operazioni CRUD (Create, Read, Update, Delete) più comuni vengano eseguite in modo standardizzato.

    È ideale per le applicazioni che hanno bisogno di una persistenza dei dati flessibile, gestendo automaticamente metadati come le date di creazione e di aggiornamento.

    #Flusso di Esecuzione

    Il funzionamento della classe segue una logica di Lazy Loading (caricamento differito):

    1. Istanziazione: Alla creazione dell'oggetto, viene memorizzato soltanto l'URI di connessione. Il database non viene ancora raggiunto.
    2. Prima Chiamata: Quando viene invocato un qualsiasi metodo di operazione (come save_payload), questo chiama internamente il metodo connect().
    3. Connessione Persistente: Il MongoClient viene creato e memorizzato nell'attributo self.client. Tutte le chiamate successive riutilizzano la stessa connessione per risparmiare risorse.
    4. Elaborazione: Il metodo esegue la logica richiesta (inserimento, ricerca, ecc.).
    5. Gestione degli Errori: Se qualcosa fallisce, la connessione viene chiusa preventivamente per evitare perdite di memoria o connessioni "bloccate".

    #Tabella dei Metodi

    MetodoDescrizione Breve
    __init__Configura l'URI di connessione (tramite argomento o variabile d'ambiente).
    connectStabilisce o riutilizza la connessione con il server MongoDB.
    close_connectionTermina la connessione attiva e pulisce il client.
    save_payloadInserisce un nuovo documento con timestamp di creazione.
    fetch_documentsCerca documenti con filtri e opzione di limite.
    update_documentsAggiorna uno o più record, aggiungendo il timestamp di modifica.
    delete_documentsRimuove i record dal database in modo definitivo.

    #Architettura e Insights

    • Gestione dello Stato: La classe utilizza il pattern Singleton-like per la connessione all'interno dell'istanza, garantendo che non vengano aperte centinaia di connessioni inutili.
    • Sicurezza dei Dati: Nel metodo di aggiornamento, il codice rimuove esplicitamente la chiave _id dal payload di aggiornamento (new_values.pop("_id", None)). Questo evita i comuni errori di MongoDB in cui si tenta di sovrascrivere l'ID immutabile di un documento.
    • Tracciabilità: L'inclusione automatica di _created_at e updated_at trasforma documenti semplici in record verificabili, facilitando il debug e l'analisi successiva dei dati.
    • Gestione degli Errori: L'uso di RuntimeError incapsula errori di rete complessi in messaggi leggibili per lo sviluppatore dell'applicazione.

    #Dettaglio della Classe

    #Classe MongoDBManager

    Descrizione

    Gestore centrale di persistenza MongoDB che incapsula il ciclo di vita della connessione e le operazioni CRUD, garantendo il riutilizzo delle risorse e la standardizzazione dei metadati.

    Argomenti

    • mongo_uri (str, opzionale): Stringa di connessione. Se omessa, cerca in os.getenv("MONGO_URI") oppure usa il valore locale predefinito.

    #Metodi

    #1. connect

    Descrizione: Garantisce che esista una connessione attiva con il database.

    Argomenti: Nessuno.

    Valori di ritorno: MongoClient (oggetto di connessione di pymongo).

    Raises: Exception in caso di errore di rete o di credenziali.

    Esempi:

    manager = MongoDBManager()
client = manager.connect()

    #2. save_payload

    Descrizione: Inserisce un dizionario nel database e aggiunge la data di creazione.

    Argomenti:

    • database_name (str): Nome del database.
    • collection_name (str): Nome della collezione.
    • payload (dict): Dati da salvare.

    Valori di ritorno: dict contenente lo stato e l'ID generato.

    Raises: RuntimeError se l'inserimento fallisce.

    Esempi:

    manager.save_payload("log_db", "events", {"event": "login_success"})

    #3. fetch_documents

    Descrizione: Individua i documenti che corrispondono ai criteri indicati.

    Argomenti:

    • database_name (str): Nome del database.
    • collection_name (str): Nome della collezione.
    • filter (dict): Filtro di ricerca (es: {"status": "active"}).
    • limit (int): Quantità massima di risultati.

    Valori di ritorno: List[dict] (Lista dei documenti trovati).

    Raises: RuntimeError.

    Esempi:

    users = manager.fetch_documents("app", "users", {"age": {"$gt": 18}}, limit=10)

    #4. update_documents

    Descrizione: Modifica i documenti esistenti e registra la data della modifica.

    Argomenti:

    • filter (dict): Criterio per trovare i documenti.
    • new_values (dict): Dati da aggiornare.
    • multi (bool): Se True, aggiorna tutti i documenti trovati; se False, solo il primo.

    Valori di ritorno: dict con metriche (matched_count, modified_count).

    Raises: RuntimeError.

    Esempi:

    manager.update_documents("app", "users", {"id": 1}, {"status": "premium"})

    #5. delete_documents

    Descrizione: Rimuove definitivamente i documenti dalla collezione.

    Argomenti:

    • filter (dict): Criterio di eliminazione.
    • multi (bool): Definisce se eliminare uno o tutti i record trovati.

    Valori di ritorno: dict con deleted_count.

    Raises: RuntimeError.

    Esempi:

    manager.delete_documents("app", "temp_data", {"expired": True}, multi=True)
